# OpenWrt Cookbook Organization Plan

## 1. Overview
The current `v14` OpenWrt Cookbook Pipeline contains highly organized Markdown instruction files (numbered `00-` to `10-`) but lacks aligned hierarchical structure for the physical data payload operating across those stages. This plan intends to map the necessary pipeline states to concrete folders, implement standard naming conventions, and prepare the final integration hooks to the primary `docs4ai` pipeline.

## 2. Recommended Folder Reorganization

**Current State:** 
The `artifacts/` folder houses an un-sequenced mix of configurations (`authoring`, `registry`, `scoring`) and data payloads (`scenario-packets`, `results`, `runs`, `tests-*`).

**Proposed Sequence Folders:**
Move and rename sub-folders in `artifacts/` (or the project root) to use the `XX-` sequential naming convention. This establishes a definitive human-readable execution flow:

*   **`01-tests-bank/`** (was `tests-full`): Holds raw, un-grouped test scenarios.
*   **`02-answer-keys/`** (was `tests-keys`): Holds the canonical truths.
*   **`03-test-batches/`** (was `tests-batches`): Holds the human-orchestrated domains of test groupings.
*   **`04-evaluation-results/`** (was `results`/`runs`): Raw outputs generated by the AI test-takers.
*   **`05-scoring-outputs/`** (was `scoring` outputs): Processed scorecards and calibration fixtures.
*   **`06-cookbook-templates/`** (was `templates`/`authoring`): Drafts and outlines based on failure analysis.
*   **`07-staging/`**: The final destination for generated artifacts.

## 3. Prompts & Documentation Structure

All AI prompt files need a centralized home where the human operator knows to find them.
*   **Move:** Ensure all prompt templates (e.g., test generation, scoring `v4`, failure synthesis, review) are located predictably, possibly in `docs/development prompts/` or a dedicated `prompts/` root folder.
*   **Readme Integration:** The `README.md` must be updated to index all step-by-step instructions. The user should be able to open the README and see: *Step 1: Test Admin. Use Prompt A located at Path B, run against Batch C.* 

## 4. Final Delivery Mechanism

The core Docs4AI architectural need is predictable state management. 
*   **Action:** Establish a JSON configuration marker.
*   **Where:** `/docs/plans/v14/openwrt-cookbook/latest_cookbook_staging.json`
*   **Content:** A simple pointer dictating which staging child folder contains the verified release context.
    ```json
    {
       "status": "ready",
       "latest_run": "cookbooks-129482",
       "path": "./07-staging/cookbooks-129482/"
    }
    ```
When the human operator reviews and accepts a cookbook run, they update this JSON file. The top-level DOCS4AI pipeline parses this file to harvest the finalized `.md` assets for the final compilation.
